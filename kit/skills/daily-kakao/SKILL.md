# 카톡·반영기 설치 (화면 제어)

Apps Script 템플릿 프로젝트: TFT가 공유한 「팀 데일리 발송기 템플릿」 링크(kit/README.md). 이 프로젝트에 Code.gs(카톡)·Site.gs(사이트 반영)·Market.gs(지표)가 들어 있다. 코드는 고치지 않고 **스크립트 속성**만 채운다.

## A. Apps Script 사본 (약 10분)
1. 템플릿 링크를 연다 → 왼쪽 **개요(ⓘ)** → 오른쪽 위 **사본 만들기**. 사본 이름을 `<name> 발송기`로 바꾼다.
2. **프로젝트 설정(⚙)** → 맨 아래 **스크립트 속성 → 스크립트 속성 추가**로 Claude가 넣는다(한글 값은 키보드 입력이 안 먹을 수 있어 붙여넣기 방식으로 넣는다):
   `NEWSLETTER_ID`(newsletter.yaml id), `NEWSLETTER_NAME`(name), `SITE_URL`(site_url), `GITHUB_REPO`(github_repo) → **스크립트 속성 저장**.
3. **배포 → 새 배포** → 유형 **웹 앱** → 다음 사용자 인증 정보로 실행 **나**, 액세스 권한 **모든 사용자** → **배포**.
   '액세스 승인' 팝업은 내장 브라우저 정책상 **사람이 눌러야** 열린다. [직접] "'액세스 승인' 클릭 → 본인 인증(패스키 등) → '고급' → '<프로젝트>(으)로 이동(안전하지 않음)' → 허용". 본인이 만든 스크립트라 정상이다. 권한 목록에 Gmail 전체 권한이 보이는 이유(초안 읽기·정리)를 미리 설명한다.
   팝업이 열려 있는 동안에는 다른 탭 이동이 막힌다 → 허용이 끝난 뒤 다음 단계.
4. 배포 결과의 **웹 앱 URL**(…/exec)을 복사해 스크립트 속성 `WEB_APP_URL`에 넣는다(비밀 값 아님, Claude가 입력).

## B. 카카오 디벨로퍼스 앱 (약 10분, 2026-11 새 콘솔 기준)
5. `developers.kakao.com/console/app` → **앱 생성**: 앱 이름 `<name> 테스트`(또는 `<name>`), 회사명 `하나캐피탈`, 카테고리 **뉴스/잡지**, 앱 대표 도메인 `https://<아이디>.github.io`, 운영정책 확인란 체크 → 저장.
   (카카오 서비스로 오인될 이름은 쓰지 않는다. 기존 앱(특히 운영 중인 앱)은 열지도 고치지도 않는다.)
6. **앱 설정 › 플랫폼 키 › REST API 키 카드의 ⋮(수정)** 화면에서:
   - **카카오 로그인 리다이렉트 URI** 첫 칸에 WEB_APP_URL을 그대로 넣고 **저장**(Claude가 입력).
   - 같은 화면 **클라이언트 시크릿**(카카오 로그인 줄)은 새 키에서 **기본 ON**이다. 끄지 않는다.
   - [직접] "이 화면 맨 위 **REST API 키**와 **클라이언트 시크릿 › 카카오 로그인 › 코드**를 복사해 Apps Script 스크립트 속성 `KAKAO_REST_API_KEY`·`KAKAO_CLIENT_SECRET`에 붙여넣고 저장해 주세요." (Claude는 값을 읽어 옮기지 않는다)
7. **제품 설정 › 카카오 로그인 › 일반 › 사용 설정** 스위치 ON → 확인 대화상자 **활성화**.
8. **카카오 로그인 › 동의항목 › 접근권한 › 카카오톡 메시지 전송(talk_message) › 설정** → **선택 동의**, 동의 목적 "매일 아침 팀 데일리 요약을 본인 카카오톡(나와의 채팅)으로 보내기 위해 사용" → 저장.
   (창이 좁으면 표 오른쪽 '설정' 버튼이 잘린다 → 창을 넓히거나 해당 행 버튼을 스크립트로 누른다)
9. **앱 설정 › 제품 링크 관리 › 웹 도메인 등록**: `https://<아이디>.github.io` (경로 없이) → 저장. 카톡 메시지 속 링크가 이 도메인이어야 열린다.

## C. GitHub 토큰 (약 5분)
10. daily-github 3절. [직접] 토큰 생성·복사 → 스크립트 속성 `GITHUB_TOKEN`에 붙여넣기.

## D. 연결·시험 (약 10분)
11. 편집기 위 함수 목록에서 **setup** 선택 → **실행**. (처음이면 권한 승인 [직접])
    실행 로그의 **발신자 연결 주소**(…/exec?owner=…)를 브라우저로 연다 → [직접] 카카오 로그인·'카카오톡 메시지 전송' 동의 → "발신자 연결 완료".
12. **testToMe** 실행 → 교육생 카톡 '나와의 채팅'에 "[시험] … 연결 확인"이 오면 성공.
13. **checkAll** 실행 → 모든 줄이 OK인지 확인. 없음·실패가 있으면 그 줄의 항목을 다시 한다.
14. newsletter.yaml `kakao_api` = WEB_APP_URL. (사이트 '카카오톡으로 받기' 버튼이 이 주소로 신청을 보낸다)

## 문제가 생기면
| 증상 | 확인 |
|---|---|
| 카카오 화면 KOE006 / redirect 오류 | 6단계 리다이렉트 URI가 WEB_APP_URL과 한 글자도 다르지 않은지 |
| KOE101 / 앱 키 오류 | 6단계 KAKAO_REST_API_KEY 값(앞뒤 공백) |
| 토큰 발급 실패 invalid_client / KOE010 | 6단계 KAKAO_CLIENT_SECRET을 넣었는지(새 앱은 시크릿 기본 ON) |
| 허용되지 않은 링크 | 9단계 웹 도메인 = SITE_URL의 https://아이디.github.io |
| insufficient scopes | 8단계 동의항목, 11단계 동의 화면에서 '카카오톡 메시지 전송'에 체크했는지 |
| GitHub 쓰기 실패 401/403 | 토큰 만료·저장소 선택·Contents 쓰기 권한 |
